# P0.2 direct vertical drag-to-pitch

1. **Files changed for this milestone:** `frontend/src/utils/pitchDrag.ts` (new), `frontend/src/utils/scoreInteraction.ts`, `frontend/src/utils/scoreRenderer.ts`, `frontend/src/components/MusicSheetViewer.tsx`, `frontend/src/components/RecognitionReview.tsx`, `frontend/tests/pitch-drag.test.mjs` (new), `backend/tests/test_p02_pitch_drag.py` (new), and this report. Existing accepted uncommitted work was preserved. No backend application code changed.
2. **Renderer/hit architecture:** extends `bindRenderer` → `bindScore`; OSMD source semantics still resolve a unique canonical event ID to its particular notehead. Shared unison heads remain unbound. OSMD is only a rendering/interaction adapter.
3. **Gesture:** primary pointer down on a safely mapped pitched note captures the pointer. Vertical movement starts a UI-only preview. Horizontal movement is ignored; preview X remains anchored to the original note. Pointer release resolves its actual Y and emits at most one edit. Cancellation/lost capture cleans up without editing.
4. **Threshold:** 5 client pixels of vertical movement. Ordinary click/keyboard selection remains intact. Completed drag clicks are suppressed so they cannot trigger a second selection action. Returning to the original pitch makes no edit.
5. **Geometry:** five horizontal, evenly spaced rendered `ParentStaffLine.StaffLines`, plus the staff line's absolute OSMD origin. The bounded lane extends three line spacings beyond the top and bottom lines. Tab/non-five-line staves are excluded. The original rendered note Y must agree with canonical pitch/clef within one-quarter line spacing before dragging is bound.
6. **Clef:** uses the event's XML-bound effective `clef.fields`, including G/F/C sign, line 1–5 and supported clef octave change. No global treble default. Missing, duplicate or unsupported context fails safely. Canonical/rendered position mismatch also fails safely, including unsupported octave-shift engraving.
7. **Mapping:** clef reference pitch establishes the bottom-line diatonic index. `round((bottomLineY - pointerY) / (lineSpacing / 2))` gives the target staff step. The existing semantic `movePitch` resolves destination letter/octave/key alteration. This supports adjacent positions, multiple positions, octaves and downward movement.
8. **Fit/zoom:** reuses `scorePoint`, inverse SVG screen CTM and OSMD pixels-per-unit. CTM accounts for CSS scaling, viewBox, page offset and scroll; target pitch is independent of presentation scale. Threshold remains in client pixels for consistent gesture activation.
9. **Preview:** a temporary SVG group shows a snapped position dot and pitch label (e.g. C5), anchored to original X; invalid targets show a cancellation label. It is removed on finish/disposal. No canonical XML edit or OSMD rerender occurs during movement.
10. **Drop command:** `PATCH events/{existingId}` with only `{ pitch: { step, octave, alter } }`, via existing `change`/`perform` and revision protection. Read-only Transposed, busy/expired, insertion and tie-target modes disable dragging.
11. **Same-event proof:** adapter test verifies the mapped event ID is the commit target. API regression verifies C4 → C5 retains ID, measure, onset, duration, voice and staff. No insertion/deletion is involved.
12. **Preservation:** existing preservation patcher changes pitch only. Tests verify note value/dots representation, exact duration, Normal/Small, grace/duration-bearing state, verse lyrics, accidental attributes, evidence IDs, neighboring events, comments, slurs and unrelated XML. Provenance records the correction through the existing path while retaining evidence identity.
13. **Accidentals:** NONE remains absent and follows destination event key context; it never becomes explicit Natural. Supported explicit natural/sharp/flat/double-sharp/flat-flat signs retain their exact alteration and attributes. No enharmonic guessing. Unsupported or inconsistent explicit spellings fail safely because the existing patcher cannot guarantee their exact preservation. Returning to the starting staff position retains the original sounding pitch.
14. **Invalid drop:** outside the bounded original lane, overlapping another staff lane on the same rendered page, missing/ambiguous clef, unavailable CTM, unsupported geometry/sign, cancellation or disabled interaction produces no PATCH, partial mutation or history entry.
15. **Relationships:** ties/slurs remain on the same events. API test verifies existing tie start/stop data survives and pitch mismatch surfaces in existing validation. No tie endpoint repair or redesign.
16. **Undo/redo:** one completed pitch drag uses one existing correction-history operation. API tests verify exact XML restoration for Undo and Redo, including C4 → C5 → C4 → C5.
17. **Lifecycle:** existing pitch correction invalidates VERIFIED state; stale transposition is cleared through the existing review `onChange` lifecycle. API test verifies edited score is REVIEW_REQUIRED and cannot transpose before re-verification. No verified-master changes.
18. **Frontend tests:** all nine test files pass with `node --test tests/*.test.mjs`. New focused file contains 15 passing cases for pitch resolution, clefs, accidental policy, threshold/click, horizontal displacement, one edit, cancellation/no-op, zoom equivalence and renderer binding. Existing selection, insertion, symbols, lyrics, source grouping, switching and lifecycle regressions pass.
19. **Backend tests:** six new focused API regressions pass; full suite: **683 passed**. Command: `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPATH=. .venv/bin/pytest -q` from backend. Tests ran outside the filesystem sandbox after TestClient startup stalled inside it. Plugin autoload disabled to avoid an unrelated installed ROS pytest plugin's missing dependency. Two existing test-client deprecation warnings remain.
20. **Lint:** `npm run lint` passes.
21. **Build:** `npm run build` passes (TypeScript and Vite). Existing large-bundle warning remains.
22. **Whitespace:** `git diff --check` passes; new files also checked with `git diff --no-index --check /dev/null <file>` and produced no whitespace errors.
23. **Limitations:** bounded five-line G/F/C clef dragging only; ambiguous overlapping lanes, shared unison heads, unsupported explicit signs/engraving and missing structural context use existing fallback controls. Geometry and DOM tests are automated fixtures; **no real-browser acceptance is claimed**. Manual acceptance should include benchmark source-system grouping, actual notehead capture, touch input, ledger positions, Fit/zoom, cancelled drops and verified/transposed lifecycle. Source layout algorithm and source bytes were not changed.
24. **Repository safety:** nothing was staged, committed or pushed. No reset, restore, clean, stash or discard was performed. Implementation and validation are complete; no publication action follows.
